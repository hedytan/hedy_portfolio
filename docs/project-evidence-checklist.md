# 两个项目的素材与结果记录

页面主线：观察到的问题 → 关键设计选择及代价 → 实际使用 → 初步反馈与下一步。
只用真实 App 画面。无需整份 PPT，也无需为所有功能补图。

## FitsApp：优先补这 3 组
1. **目标设置**：从选择目标到确认的一段短录屏，证明用户能设定自己的目标。
2. **步数与成长**：同一种树在较低/较高步数时的两张高清截图，或真实更新录屏。说明是实时数据还是演示数据；不要将演示计数写成真实运动提升。
3. **定制**：已有录屏可用。若方便重录，展示选择树 → 返回主页看到选择生效；关闭 AssistiveTouch 浮钮。

可选：之前的目标页导航方案（菜单栏 vs 滑动）和最终方案。旧材料确实展示了两种导航，但目前没有选择依据，因此页面不声称哪种通过测试胜出。
待确认：你个人负责的研究、界面、代码和测试范围；步数实际来自 HealthKit、Core Motion 还是演示数据。

## Resonance：优先补这 3 组
1. **发布 moment**：选择心情 → 写下想法 → 添加 demo/歌曲 → 发布。一段真实完整操作。
2. **听音乐并回应**：打开 moment → 播放选定音频 → 触发 Connection。演示核心价值。
3. **取舍对比**：早期 Pinterest 式内容板与当前 feed 各一张，最好同尺寸。证明从内容组织转向情绪表达的变化。

现有 feed、express、moment、connection 截图可继续使用。录屏建议每段 15–30 秒、保持原始竖屏比例、无剪辑软件外框；不需要配音。

## 真实量化结果怎么补
当前已确认：两个项目均经过熟人小范围体验，反馈正向。没有确认人数、任务完成记录或评分，所以公开页不展示虚构百分比。

有记录后可报告：
- “X / N 位参与者独立完成目标设置”（分母为实际尝试该任务的人）。
- “X / N 位参与者能正确解释树木成长规则”。
- “X / N 位参与者完成发布、播放和回应流程”。
- 若确实收集了统一评分：“清晰度评分中位数 X / 5，N 人”。不要将口头正面反馈换算成评分。

小样本优先展示 X / N，而非百分比。没有计时就不报告耗时；没有前后对照就不报告提升；正面反馈不等于更健康或更深连接。
